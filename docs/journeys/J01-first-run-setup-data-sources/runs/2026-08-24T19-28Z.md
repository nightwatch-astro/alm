## Environment note

Triage `environment`, recorded here only.

`.mcp.json` on this commit does list the `tauri` MCP server (line 36,
`@hypothesi/tauri-mcp-server@0.11.2`), and the primary checkout has been merged
past it — but no `tauri` MCP tool was available in the validating agent
session. Cause: Claude Code binds MCP servers at session start, and this
session's CLI process started `2026-08-23 22:06:01` while `.mcp.json` first
gained the entry in this working tree at `2026-08-24 22:38:58` — roughly 25
hours later. A running session cannot pick up a newly added server, so
astro-plan-skfwo's condition is fixed on disk and still inactive in any session
that predates the merge. Restarting the agent session is the fix; nothing about
the repo or the host needed changing.

Driving proceeded over the bridge's own WebSocket protocol instead
(`{id,command,args}` → `{id,success,data,error}` on `ws://127.0.0.1:9223`,
commands `execute_js` / `get_window_info`), which is the exact transport the
MCP server itself uses, run from the host so the bridge stays bound to
loopback. Fidelity is therefore unchanged; only the client differs.
