## Environment note

Triage `environment`, recorded here only; nothing filed.

`.mcp.json` at this commit does list the `tauri` MCP server (line 36,
`@hypothesi/tauri-mcp-server@0.11.2`) and the primary checkout has been merged
past it, but no `tauri` MCP tool was available in the validating agent session.
Claude Code binds MCP servers at session start: this session's CLI process began
`2026-08-23 22:06:01`, while `.mcp.json` first gained the entry in the working
tree at `2026-08-24 22:38:58`. A running session cannot pick up a newly added
server, so astro-plan-skfwo's condition is fixed on disk and still inactive for
any session older than the merge; restarting the session is the fix.

Driving therefore used the bridge's own WebSocket protocol directly
(`{id,command,args}` → `{id,success,data,error}` on `ws://127.0.0.1:9223`), run
from the host so the bridge stayed bound to loopback. That is the exact transport
`@hypothesi/tauri-mcp-server` uses, so the fidelity is identical and only the
client differs. Full reusable recipe published as a comment on astro-plan-mg6h8.
